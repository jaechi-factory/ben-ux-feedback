# 요청 예시

화면 이미지를 올린 뒤 아래 문장을 복사해서 붙여 넣어요. 대괄호 안은 내 상황에 맞게 바꿔요. 어떤 요청이든 심각도, 근거, 수정안이 붙은 지적으로 돌아와요.

## 1. 화면 이미지 리뷰

가장 기본이에요. 맥락을 함께 주면 "이 화면이 그 문제를 푸는가"까지 봐요. 모르는 항목은 비워도 돼요.

```
첨부한 화면을 디자인 가이드라인으로 검토해 줘.
심각한 지적부터 알려 주고, 심각한 건 수정 후 모습까지 써 줘.

## 어떤 제품인가요?
## 달성하고자 하는 목표가 무엇인가요?
## 해결하고자 하는 문제는 무엇인가요?
## 왜 이 문제를 겪고 있을까요?
## 어떻게 해결하고자 하나요?
## 이 개선을 통해서 유저가 얻는 기대효과는 무엇인가요?
## 이 개선을 통해서 회사가 얻는 기대효과는 무엇인가요?
## 디자인 결과물 링크나 이미지
```

## 2. 가상 UT 포함

연령대가 다른 가상 사용자의 반응까지 보고 싶을 때예요.

```
첨부한 화면 3장을 검토하고, 가상 UT도 같이 해 줘.
청년, 중년, 노년 가상 사용자 3명이 이 순서대로 화면을 걸어 보게 하고,
막히는 곳은 지적에 이어 줘.
주요 과업: [예: 오늘 쓴 돈을 기록하기]
```

## 3. 가상 UT 제외

화면 지적만 빠르게 받고 싶을 때예요.

```
첨부한 화면을 검토해 줘. 가상 UT는 빼고 화면 지적만 줘.
중간과 낮음은 제목과 제안만 표로 줄여도 돼.
```

## 4. 문구만 검토

화면 속 글만 보고 싶을 때예요.

```
첨부한 화면의 문구만 검토해 줘.
버튼, 안내, 오류 문구를 수정 전과 수정 후로 나란히 보여 줘.
전문 용어나 사용자가 못 알아들을 말이 있으면 먼저 알려 줘.
```

## 5. 흐름 검토

여러 화면의 이어짐과 빠진 분기를 볼 때예요. 화면은 순서대로 올려요.

```
첨부한 화면 [5]장은 [가입]부터 [첫 사용]까지의 흐름이야. 순서대로 올렸어.
화면 하나하나보다 흐름을 봐 줘.
- 사용자가 길을 잃는 곳
- 빠진 화면이나 분기(오류, 빈 상태, 되돌리기)
- 화면 사이에서 말이나 구성이 달라지는 곳
```

## 6. 수정한 화면 다시 확인

한 번 받은 지적을 고친 뒤에 써요.

```
지난번 지적 중 [F01, F02]를 고친 화면이야.
같은 기준으로 다시 보고, 고쳐졌는지와 새로 생긴 문제가 있는지 알려 줘.
```

## 7. 시안 비교

같은 화면의 시안 여러 개 중 무엇이 나은지 볼 때예요.

```
첨부한 [3]개는 같은 화면의 시안이야. 무엇이 가장 좋은지 순위를 매기고,
시안마다 아쉬운 점과 수정안, 다른 시안에서 가져올 점을 알려 줘.
```

## 8. 만들기 전에 기준만 받기

새 화면을 기획하거나 시안을 만들기 전에 지킬 기준만 받고 싶을 때예요.

```
[환불 신청 화면]을 새로 설계할 거야. 아직 시안은 없어.
가이드라인에서 이 화면에 해당하는 원칙과 시작 전에 답해야 할 질문을 알려 줘.
```
